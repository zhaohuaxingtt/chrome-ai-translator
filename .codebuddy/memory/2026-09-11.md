## 迭代：悬浮球控制 + 默认不翻译（ticket 01–03 完成）

用户诉求：默认自动翻译所有页面不友好 → 改为**按需翻译**。

**已确认的决策：**
- 打开页面**默认不翻译**（保持原文）
- 右下角**常驻悬浮球**，点击展开菜单弹窗
- 菜单主操作「翻译本页」是**一次性**的（刷新后回到原文，不记忆）
- 用户只选了核心范围，语言切换/站点记忆留给后续

**实现：**
- `ExtensionSettings` 新增 `autoTranslate`（默认 `false`）。**关键：没有直接改 `enabled` 默认值**——用户之前在 Popup 启用过，`chrome.storage` 存储值优先于默认值，改默认值对他无效，新字段才能生效。
- content script 新增运行时状态 `pageTranslationEnabled`（初始 = `enabled && autoTranslate`）、`pageTranslated`；`runTranslateGuarded` 未开启时直接返回，因此 observer 自愈也不会绕过按需模式。
- 新增 `src/content/floating-ball.ts`：注入式（root + 3 个回调），样式全内联并对关键项 `!important`，事件 `stopPropagation` 防冒泡触发宿主页面逻辑；状态色：未翻译蓝 `#0969da` / 已翻译绿 `#1a7f37` / 忙碌橙 `#9a6700`；深色菜单保证任何页面背景可读。
- `content/index.ts`：启动时若 `enabled=false` 连球都不显示；否则创建球并按 `autoTranslate` 决定是否自动翻译；`enable/disablePageTranslation` 供球调用（取消时删除译文节点 + 清标记，原文从未被改写所以直接删译文即可）。
- 页面侧设置类型收敛为 `PageSettings`（enabled/autoTranslate/targetLang/excludedHosts），**刻意不含 API 凭据**，把「密钥只归 Background」的安全边界写进类型。

82 tests 全绿（新增 floating-ball 9 项：渲染、菜单开合、三个回调、状态色、不冒泡、destroy）。
