## 修复：Content Script 调不到 openOptionsPage

用户点悬浮球「打开设置」报 `chrome.runtime.openOptionsPage is not a function`。

**根因：** Content Script 运行在网页隔离环境，只能访问 chrome API 的**受限子集**，`openOptionsPage` 只属于扩展页面（popup / options / background）。但 `@types/chrome` 提供了类型声明 → **编译期不报错、运行时才炸**（"类型正确但运行时受限"的典型陷阱）。

**修复：** 新增 `OPEN_OPTIONS_REQUEST` 消息 + `isOpenOptionsMessage` 守卫；Content Script 发消息 → Background 收到后调用 `openOptionsPage`。新增 messages 守卫测试 3 项，85 tests 全绿，已推送 `eb8bed9`。

**Content Script 可用 API 备忘（本项目相关）：**
- ✅ `chrome.storage`、`chrome.runtime.sendMessage` / `connect` / `getURL` / `getManifest` / `onMessage`、`chrome.i18n`、`chrome.dom`
- ❌ `chrome.runtime.openOptionsPage`、`chrome.tabs`、`chrome.scripting`、`chrome.alarms`、`chrome.contextMenus`

## 样式改进：译文按容器类型区分渲染

用户反馈「按钮翻译出来很丑」（DeepSeek 平台截图：`Create new API key` 按钮被译文撑变形，侧边栏原文+译文堆叠拥挤）。

**根因：** 渲染器无条件 `display: block`，所有译文都独占一行，按钮/导航这类紧凑元素被撑高。

**修复：**
- 新增 `src/shared/compact-element.ts`：`isCompactElement`（BUTTON/LABEL/SUMMARY/TH/TD、`role=button`、class 含 btn/button）+ `isInCompactContainer`（向上探查 4 层）。**提取器与渲染器共用同一套判断**，避免「按紧凑渲染、却按段落提取」的错配。
- 渲染器：紧凑容器 → `display:inline` + 括号包裹（`(译文)`）；段落类 → `display:block` + `margin-top`。两者都带弱化样式：`font-size: 0.94em`、`opacity: 0.85`、`line-height: 1.5`。
- 提取器：`BLOCK_TAGS` 增加 `BUTTON`；`findContainer` 遇到紧凑元素也返回（按钮文本独立成块，不归到外层容器）。

renderer 测试 5 → 8 条，88 tests 全绿，已推送 `76aad3c`。

## 工具教训：同一文件的多个 replace 不能并行

一个批次里对**同一文件**发两个 `replace_in_file` 会互相覆盖（后写入的基于旧内容），表现为「工具报告成功但改动丢失」。本次症状：typecheck 报新加的 import「已声明但未使用」。

**规则：同一文件的多处修改必须串行；不同文件才能并行。**
