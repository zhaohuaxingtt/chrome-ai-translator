# 悬浮球控制与「默认不翻译」

Status: draft

## Problem Statement

当前插件默认对**所有**页面自动翻译：打开任一外文站就会立刻发起几十上百次 API 请求。这既打扰阅读（很多页面用户并不想翻译），也造成不必要的 token 消耗——用户抱怨「默认翻译页面很不友好」。

## Solution

改为**按需翻译**：页面默认保持原文，右下角常驻一枚悬浮球，点开是菜单，由用户主动决定当前页是否翻译。

### 已确认的决策

| 决策点 | 结论 |
| ------ | ---- |
| 打开页面的默认行为 | **不翻译**，保持原文 |
| 控制形态 | **常驻悬浮球**（页面右下角） |
| 点击悬浮球 | 展开**菜单弹窗**（不是单一开关） |
| 菜单主操作 | 「翻译本页」——**一次性**，刷新后回到原文，不记忆 |

## User Stories

1. 作为一个用户，我打开任意网页时希望它保持原样，不要自动翻译，以免打扰和浪费额度。
2. 作为一个用户，我想在页面右下角看到一枚悬浮球，随时知道插件可用。
3. 作为一个用户，我想点开悬浮球看到菜单，里面有「翻译本页」的开关。
4. 作为一个用户，我点「翻译本页」后希望当前页被翻译。
5. 作为一个用户，我再点一次希望取消翻译，页面恢复原文。
6. 作为一个用户，我希望悬浮球能反映当前页状态（已翻译/未翻译）。
7. 作为一个用户，我希望菜单里有「打开设置」入口。
8. 作为一个用户，我不希望悬浮球挡住页面内容，能把它隐藏起来（本次会话）。
9. 作为一个用户，我不希望悬浮球的点击被页面脚本拦截或误触发页面逻辑。
10. 作为一个用户，我希望悬浮球在浅色/深色页面上都能看清。

## Implementation Decisions

- **默认关闭**：`DEFAULT_SETTINGS.enabled` 改为 `false`。已有用户的存储值优先，不受影响。
- **悬浮球由 Content Script 注入**，运行在 isolated world，不影响页面 JS。
- **样式全部内联 + 高 z-index + `!important` 关键项**：宿主页面 CSS 千差万别，必须自保。
- **事件隔离**：球与菜单的点击一律 `stopPropagation`，避免冒泡到页面触发页面自身逻辑。
- **位置持久化**：拖动后的位置记在设置里（可选，先做固定右下角 + 隐藏能力）。
- **可测性**：悬浮球的「状态与菜单行为」抽成可注入依赖的模块（注入 document 与回调），不依赖 Chrome API，可在 DOM 环境里单测。
- **翻译/取消**：复用现有 `translatePage`（翻译）与逐块 `revertTranslation`（取消）。取消需要记录本页已渲染的块。

## Testing Decisions

- 只测外部行为：给定 DOM 与回调，验证渲染出的球、菜单开合、状态切换回调被正确触发。
- 覆盖：默认不自动翻译、点击球展开/收起菜单、点「翻译本页」触发回调、已翻译态的视觉状态、隐藏后不再渲染。
- 不测具体像素/颜色等实现细节。

## Out of Scope

- 悬浮球菜单里的语言快速切换、站点级记忆（「总是翻译本站」）——留给后续迭代。
- 快捷键、选中文字翻译气泡。
- 拖拽位置的持久化（本轮先做固定位置 + 可隐藏）。

## Further Notes

- 「翻译本页」是一次性的：刷新页面后回到未翻译态，符合「默认不翻译、不记忆」的定位。
- 后续若要加「总是翻译本站」，需在设置里增加站点白名单，与本方案不冲突。
